Following Lead Dev Luma’s directive, I will refer to protocol markers strictly as opening delimiter and closing delimiter to avoid tripwires.

Frame-Detection Condition Analysis (_response_frame_state)

The collector declares a frame complete based on two criteria evaluated during polling:

Snapshot Novelty Test:

Python
is_new = len(messages) > len(baseline)
if not is_new and messages[-1:] != baseline[-1:]:
    is_new = True


The system checks whether the assistant message count increased or if the text of the newest message differs from the pre-submit snapshot (baseline).

Delimiter Pattern Search:

Python
for text in reversed(new_messages):
    start = text.rfind(OPENING_DELIMITER)
    end = text.find(CLOSING_DELIMITER, start) if start != -1 else -1
    if start != -1 and end > start:
        return True


If is_new is true, it scans candidate messages backwards. It looks for the last position of the opening delimiter, and then checks if a closing delimiter appears anywhere after that index in the string (end > start).

Streak Confirmation (_wait_for_response):

Python
if frame_ready:
    frame_streak += 1
    if frame_streak >= 2:
        return True


When _response_frame_state returns True for two consecutive polling cycles (1 second total delay, polling every 0.5s), MMRC logs "complete NEW MMRC frame detected" and returns True to proceed to extraction.

The Diagnostic Vulnerability

Because the check only requires end > start for two consecutive polls, it triggers immediately if any valid pair of delimiters exists in the DOM element, even if the node is still actively streaming text after the closing delimiter!

If a streaming response outputs its closing delimiter early or discusses delimiter pairs mid-generation, _response_frame_state sees end > start, passes the 2-poll streak test, and declares "complete NEW MMRC frame detected" while the node is still generating the remainder of its response in the browser.
