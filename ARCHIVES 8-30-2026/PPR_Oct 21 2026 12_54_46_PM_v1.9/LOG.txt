1. The original objective
Spiffy's Gift is intended to be a small, affordable or donation-supported retro game inspired by the fun of finding and exploiting bugs in games such as Skyrim.
The player discovers ways to circumvent the rules of a game while a simulated development team attempts to patch those exploits. Patches may eliminate an existing trick while creating new opportunities.
The eventual game will begin with a small, Skyrim-inspired alchemy shop containing two connected rooms:
A main shop with shelving, merchandise, a counter, a vendor, a player character, and a bucket.
A connected side room where merchandise can be moved beyond the vendor's line of sight.
Two initial exploits are planned. The player can place an upside-down bucket on the vendor's head to prevent the vendor from seeing theft, or carry merchandise into the side room before taking it. These are intended to emerge from object manipulation and visibility rules, rather than from a menu option labelled “Exploit.”
The desired presentation is retro 2D, with a point-and-click interaction style. No 3D engine is planned. All assets and software must be usable without spending money, including for a low-cost or donation-supported commercial release.
2. The architectural principle
The governing principle is the same one used in QuackSink:
“Maybe don't look at DRS/MMRC primarily as Python code. Look at it as a system of interacting state machines, and let the Python implement that model.”
— Luma
SGG is therefore being designed as a state machine implemented in Python, not as a conventional application that we intend to convert into a state machine later.
States, events, transitions, side effects, and error conditions must be explicit. File operations must have defined success and failure behavior. Future game mechanics will use the same discipline.
Cozmo's development rule is also established: Luma alone authors the code. Every revision must be a complete, new version of the source file. Cozmo does not edit code; he runs it, tests it, reports observations, and directs the creative work. Previous versions remain preserved.
3. Dependency isolation and environment
Before writing the tool, we assessed the likely dependency risks.
The chosen environment is:
Python 3.12.10, 64-bit Windows.
A dedicated SGG virtual environment at SGG\.venv.
pygame-ce==2.5.8 as the sole third-party Python dependency.
Python's standard library for configuration, paths, timestamps, logging, and related file operations.
Pygame-CE installed successfully from a prebuilt Windows wheel. The import test reported Pygame-CE 2.5.8 and SDL 2.32.10. pip check reported no broken requirements.
The root requirements.txt pins pygame-ce==2.5.8. The root .gitignore excludes .venv/, preventing the local virtual environment from being included in normal Git pushes.
The SGG environment is isolated from PPR's existing environment, preventing the game from inheriting unnecessary relay, browser, and voice dependencies—or disrupting PPR's working configuration.

SGG\assets\kenney-roguelike-rpg-pack

The transparent sprite sheet is the current asset-preview test image. The exact selection of tiles for the finished shop has not yet been finalized. Any missing artwork, including a suitable upside-down bucket or custom characters, will be created or adapted by Luma and the AI collaborators. Cozmo is not expected to do pixel art.
5. Why the first deliverable is sgg1.py
Rather than immediately building the game, the first deliverable establishes the reusable development framework.
Its responsibilities are to create an archive at startup, copy the running source into that archive, create a log whose first line is the archive name, and provide a basic interface for notes and asset inspection.
This is foundational work. It ensures that later game versions can be tested, documented, and compared without manually reconstructing which code and settings produced a run.
Archive naming and versioning
The required format is:
SGG_DDMMMYY_HR-MIN(am/pm)VX.Y
For example:
SGG_21OCT26_12-53pmV1.2
The software version is declared in the source code. Launching the same version multiple times creates separate timestamped archives without changing its version number. The version changes only when Luma deliberately creates a new code version.
Archives live under SGG\archives, beneath the launch/project directory. Each run archive contains its source snapshot and log.txt, with configuration snapshots and saved note files also kept inside the archive.
The initial V1.0 trial exposed two practical issues: archives were not placed under the desired archives directory, and note files were written to the project root. These were addressed in subsequent versions. The top-level project remains the working location for the current source and live settings.

9. Why we did things in this order
The decisions so far address five specific risks.
Dependency risk: isolate SGG from PPR before installing game libraries.
History risk: create run archives automatically so every test has its own source and log.
Usability risk: make the UI readable for Cozmo, with true black backgrounds and large white text.
Reproducibility risk: record configuration with every run while keeping ongoing preferences in the main config.
Scope risk: build and verify a small development tool before starting the visual game. This provides a stable foundation without prematurely committing to a large game engine or elaborate mechanics.
The goal is not to create a complicated framework for its own sake. It is to make the development process reliable enough that work on the actual game can proceed in small, complete, testable versions.

Only after the framework and visual assets are adequately understood will we begin implementing the game scene and its interactions.
The first game milestone will combine the visuals and the core mechanic: a shop the player can recognize, a vendor, shelves and merchandise, a movable bucket, and a second room where line of sight matters.
The central principle remains unchanged: build a small working system, observe its behavior, archive the evidence, and extend it without losing the history.
