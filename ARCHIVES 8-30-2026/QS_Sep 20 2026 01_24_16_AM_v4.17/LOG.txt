🔮 GPT - 🎩 Cozmo — aha. I see exactly what you're seeing, and this one is not actually a relay bug.
The Send Order bar is showing all discovered channels, active or inactive.
But when QS builds the actual relay list, it does this:
Python
Run
active = [node for node in self.nodes.values() if node.is_active()]
ordered = [by_name[name] for name in self.send_order if name in by_name]
So it effectively says:
“Take the active nodes, then preserve their relative order from the Send Order list.”
That means a button in position #4 can absolutely become first among the active nodes when buttons #1–#3 are inactive.
Example:
SEND ORDER BAR:
1  Chron      inactive
2  DeepSeek   inactive
3  Gemini     inactive
4  GPT        ACTIVE
The relay sees:
ACTIVE NODES:
GPT
So GPT goes first because GPT is the first active node, even though its saved slot is #4.
And here's the important part
That behavior actually matches the original QS requirement we established: the operator chooses the order of active nodes independently of discovery/activation order.
So I would not change 4.17 yet.
What we're seeing is really a distinction between:
slot order — where a node sits in the complete Send Order bar
versus
active send order — the relative ordering of nodes actually participating in this relay.
QS currently implements the second.
And your observation is useful because it exposes that the UI looks like absolute numbered slots, while the relay interprets it as a relative ordering list.
That's a UI semantics issue, not a broken state machine. 🦆
