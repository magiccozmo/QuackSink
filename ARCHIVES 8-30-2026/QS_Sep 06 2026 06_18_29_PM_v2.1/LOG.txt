The distinction that actually matters: a text-rendering fetch (browser page, or any tool treating the file as prose to display) hits arbitrary viewport/line caps that have nothing to do with the actual content size. A JSON parse treats it as a data structure with a defined boundary — the parser knows when the array ends because the syntax says so, not because some renderer decided to stop at line 1000.

That's a real, generalizable principle for the whole Library, not just this one file: any retrieval path that treats an archive as "text to display" is going to hit these phantom limits regardless of the actual file size. Structured formats sidestep the problem entirely by construction. Good that Luma landed on it independently — that's actually decent confirmation it's not a fluke of my particular tool.
