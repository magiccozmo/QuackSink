# PART 4 — CRITICAL: HOW WE SUCCESSFULLY RETRIEVED LARGE GITHUB ZIP FILES

This is the most important technical lesson from the November 2 session.

The ordinary GitHub file connectors were able to inspect repository contents and retrieve smaller files, but they returned empty contents for the large binary ZIP packages.

Dropbox's text extraction also has a file-size limitation.

Repeatedly trying the same failed download methods was not productive.

**The solution we successfully implemented was to use GitHub Actions as a binary transfer bridge.**

This method WORKED. It successfully retrieved both original F1m archives and transferred them into the assistant's working environment.

## The successful procedure

A. Identify the exact source and deployment ZIP paths in the GitHub repository.

For F1m these were:

`ARCHIVES 8-30-2026/SGG/sggweb/SGGF1.666f1m_SOURCE.zip`

`ARCHIVES 8-30-2026/SGG/sggweb/SGGF1.666f1m_COMPLETE_CLOUDFLARE_SITE.zip`

B. Inspect the repository's current main branch and obtain its exact commit SHA.

C. Create a temporary, isolated branch from that commit.

D. Add a temporary workflow under:

`.github/workflows/`

The workflow should:

- Trigger on a push to the temporary branch.
- Check out the exact branch.
- Copy the two specified original ZIP files directly from the checkout into a temporary staging directory.
- Verify they are nonempty.
- Run `unzip -t` on both.
- Calculate SHA-256 checksums.
- Record their actual file sizes.
- Upload them together using `actions/upload-artifact@v4`.
- Use short artifact retention, normally one day.

E. Query GitHub Actions for the workflow run associated with the temporary branch.

F. Inspect the run status and job steps until the job completes successfully.

G. Retrieve its artifact ID using the GitHub workflow artifact listing.

H. Use the GitHub artifact download capability:

`mcp__GitHub__download_workflow_artifact`

The successful November 2 example was:

- Workflow run ID: `41416258911`
- Artifact ID: `13127990925`
- Artifact name: `SGGF1m-baseline-transfer`

The artifact was successfully downloaded and materialized into the assistant's workspace.

I. Extract the transfer artifact. It contains the original two ZIPs, their checksum record, and file-size record.

J. Independently verify the actual extracted source and deployment ZIPs in the assistant's working environment.

This is important: the transfer artifact itself is an outer ZIP containing the two original project ZIPs. Extract the outer artifact first, then inspect the actual project archives.

**Do not revert to repeatedly trying the normal GitHub binary fetch route when it returns zero bytes. Use the proven Actions bridge.**
